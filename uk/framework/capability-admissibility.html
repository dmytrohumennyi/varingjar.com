Module 03 / 07

Спроможність і допустимість — це не одне й те саме.

Фреймворк розділяє структуру конфігурації Φ(cfg), її паспортну межу S̄(cfg) і поточну живучість S(t). Коректне рішення супервізора виникає лише з урахуванням усіх трьох.

01Після відмови система вже не є номінальною.02Чотирирівнева ієрархія: ресурс → сервіс → функція → місія.03Спроможність і допустимість — це не одне й те саме.04Валідність моделі — теж ресурс.05Реконфігурації утворюють простір трансформацій, а не список реакцій.06Часові обмеження незалежні: задача, реакція, послідовність.07Планувати треба траєкторію, а не лише наступний вузол.

Три величини

Структура, межа, поточний стан

У моделі є три різні величини: Φ(cfg) показує, які функції структурно присутні; S̄(cfg) показує, яку межу живучості ця конфігурація може мати в ідеалі; S(t) показує поточний результат тут і тепер.

0 ≤ S(t) ≤ S̄(cfg) ≤ Φ(cfg) ≤ 1

Без цього розділення супервізор плутає «функція структурно існує» з «функція реально забезпечується в потрібній якості».

Джерело в дисертації: §§2.6.3–2.6.8, 3.4

Умови допустимості

Не кожна наявна конфігурація коректна

Ресурсно допустима конфігурація не може використовувати відмовлений ресурс. Функціонально допустима конфігурація не може оголошувати активною функцію, для якої не вистачає ресурсного покриття.

Adm_Rs(cfg, ρ): активний ресурс має ρ ≥ ρmin

DecisionEngine

Рішення працює над уже обмеженою множиною

DecisionEngine не ранжує весь каталог без винятку. Він працює лише на множині конфігурацій, що пройшли перевірку допустимості, а далі обирає альтернативу за живучістю, критичністю або іншими критеріями.
