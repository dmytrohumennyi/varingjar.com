IMPLEMENTATION · DISSERTATION, CHAPTER 4

How the system is reconfigured

Six ROS2 framework modules, a configuration catalogue, and three independent real-time constraints. The architecture and its timing analysis are documented in Chapter 4 of the dissertation.

§ 4.2–4.7 · ARCHITECTURE

More than switching. A complete control loop.

The system is modelled across four abstraction levels: mission → function → service → resource. Six modules cover state assessment, decision making, safe switching, and stability supervision.

Mission → Function → Service → Resource
ModuleRole
HealthMonitorAssesses physical resource health and diagnostic inputs.
DecisionEngineSelects an admissible configuration for the current mission and state.
ReconfigManagerManages transitions, Hot Standby and Rollback.
StabilityAnalyzerChecks stability conditions of configurations and transitions.
ConfigStoreStores the catalogue of available, verified configurations.
SafetySupervisorIndependently supervises safety and inadmissible operating modes.

§ 4.10 · REAL-TIME ANALYSIS

What the timing analysis actually shows

Functional correctness does not guarantee a timely result. The dissertation evaluates task schedulability, response to a single fault, and the admissibility of repeated reconfigurations.
